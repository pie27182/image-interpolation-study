# Наборы тестовых изображений

Этот документ описывает источники изображений для экспериментов. Файлы внешних наборов не включаются в Git: их нужно получать с официальных страниц и хранить локально. Перед публикацией результатов проверьте актуальные условия лицензии и сохраните происхождение каждого файла в манифесте.

## 1. Встроенные синтетические изображения

Создайте тестовые изображения командой:

```bash
python examples/generate_test_images.py --output-dir data/synthetic --size 512
```

Генератор создаёт восемь PNG-файлов:

| Файл | Назначение |
|---|---|
| `synthetic_gradient.png` | Плавный цветовой градиент: точность и плавность |
| `synthetic_edges.png` | Шахматная решётка и вложенные квадраты: алиасинг и звон |
| `synthetic_impulse.png` | Единичный импульс: пространственный отклик фильтра |
| `synthetic_slanted_edge.png` | Наклонная ступень: размытие, выбросы и MTF-анализ |
| `synthetic_grating.png` | Периодическая решётка: муар и сохранение частоты |
| `synthetic_zone_plate.png` | Радиальный chirp: частота растёт к краям и пересекает предел Найквиста |
| `synthetic_siemens_star.png` | Звезда Siemens: направленное разрешение и муар |
| `synthetic_frequency_sweep.png` | Линейный частотный sweep: поведение от низких до сверхнайквистовых частот |

Генератор детерминированный: при одинаковом размере пиксельные данные повторяются. Синтетические изображения не заменяют фотографии, но позволяют проверять отдельные свойства алгоритмов в контролируемых условиях.

Для анализа наклонной границы можно дополнительно использовать методику Slanted Edge / MTF, например [плагин ImageJ](https://wsr.imagej.net/ij/plugins/se-mtf/index.html). Не называйте простой визуальный просмотр MTF-измерением: для него нужен отдельный алгоритм анализа ESF/LSF и документированный протокол.

## 2. TESTIMAGES / SAMPLING — основной внешний набор

- Официальная страница: [TESTIMAGES / SAMPLING](https://testimages.org/sampling/).
- Лицензия: [CC BY-NC-SA 4.0](https://testimages.org/license/).
- Описание архива: [TESTIMAGES](https://testimages.org/).
- Научная ссылка: N. Asuni, A. Giachetti, “TESTIMAGES: A Large Data Archive For Display and Algorithm Testing”, *Journal of Graphics Tools*, 17(4), 2015, pp. 113–125, [DOI: 10.1080/2165347X.2015.1024298](https://doi.org/10.1080/2165347X.2015.1024298).

В SAMPLING есть 40 эталонных RGB-изображений 2400×2400, первоначально подготовленных с глубиной 16 бит на канал. Для них также доступны многочисленные варианты меньшего разрешения и сдвигов сетки; архив сообщает о более чем 220 тысячах производных файлов.

**Важная особенность протокола:** уменьшенные версии создавались усреднением значений блоков R×R из исходного изображения. Это контролируемый сценарий, близкий к усреднению площади, но не универсальная модель любого оптического или цифрового уменьшения. Варианты со сдвигом окна полезны для оценки чувствительности к фазе/положению сетки.

Рекомендации:

1. Начните с 8-битных RGB-версий. Текущий benchmark проекта загружает изображение как RGB `uint8` и использует диапазон метрик 255; он пока не является полноценным 16-битным конвейером.
2. Запишите точное имя исходного файла, коэффициент уменьшения и идентификатор сдвига.
3. Сравнивайте изображения с одинаковой геометрией и одной и той же маской/сдвигом.
4. Проведите отдельные эксперименты на данных, созданных усреднением, и на данных, которые вы уменьшили фильтрами bilinear, bicubic и Lanczos самостоятельно.
5. Указывайте атрибуцию и цитируйте публикацию TESTIMAGES.

Архив лицензирован CC BY-NC-SA 4.0: требуется атрибуция, запрещено коммерческое использование, а распространение адаптированных материалов подпадает под условия ShareAlike. Не помещайте скачанные изображения в репозиторий без необходимости и не объявляйте их частью MIT-лицензии кода.

## 3. DIV2K — разнообразные фотографии

- Официальная страница и загрузки: [DIV2K Dataset](https://data.vision.ee.ethz.ch/cvl/DIV2K/).

DIV2K содержит разнообразные RGB-фотографии высокого разрешения. В обучающей части указаны 800 изображений с соответствующими версиями низкого разрешения для коэффициентов ×2, ×3 и ×4; валидационная часть включает 100 изображений.

На официальной странице указано, что набор предоставляется **только для академических исследований**; изображения собраны из интернета, а авторские права остаются у исходных владельцев. Поэтому:

- не зеркалируйте и не коммитьте архив в этот репозиторий;
- не используйте набор для коммерческого продукта без отдельного разрешения;
- записывайте обозначение split (train/validation), имя файла и вариант уменьшения;
- при необходимости публикации изображений получите разрешения у правообладателей.

DIV2K полезен как дополнительная проверка на естественных изображениях, но его готовые LR-версии следует считать отдельным сценарием деградации, а не универсальным эталоном.

## 4. Источники, требующие дополнительной проверки прав

### USC-SIPI Image Database

[Официальная база USC-SIPI](https://sipi.usc.edu/database/) содержит классические фотографии, текстуры, аэроснимки и тестовые изображения. Однако [страница об авторских правах](https://sipi.usc.edu/database/copyright.php) прямо предупреждает, что университет не владеет правами на многие изображения, а статус части файлов неизвестен. Отдельные изображения, созданные в USC (например, некоторые синтетические тестовые таблицы), обозначены как свободные для исследовательского использования.

Используйте только конкретные файлы, для которых статус прав отдельно установлен. Не считайте всю базу единой свободной коллекцией и не полагайтесь на нее для публикации без проверки.

### Kodak Lossless True Color Image Suite

Набор Kodak широко встречается в старых исследованиях качества изображений, но доступность файлов на стороннем зеркале сама по себе не устанавливает лицензию. Не включайте эти изображения в распространяемый проект и не называйте их открытыми без явного разрешения правообладателя.

## 5. Манифест и структура локальных данных

Рекомендуемая структура:

```text
data/
  README.md
  manifest.example.csv
  synthetic/          # генерируется скриптом; не коммитится
  external/
    testimages/
    div2k/
```

Скопируйте `data/manifest.example.csv` в `data/manifest.csv` и укажите для каждого используемого файла как минимум:

- относительный путь и имя файла;
- набор, URL источника и идентификатор изображения;
- лицензию и строку атрибуции;
- SHA-256 скачанного файла;
- исходные размеры, число каналов и глубину цвета;
- вариант уменьшения/сдвига и дополнительные преобразования.

Не сравнивайте численные результаты, пока не зафиксированы версии исходных изображений и сценарий создания входа низкого разрешения.
