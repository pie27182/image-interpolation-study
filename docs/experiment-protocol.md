# Suggested experiment protocol for the thesis

This is a reproducible starting protocol. Adjust image counts, scale factors
and statistical analysis to the supervisor's requirements.

## 1. Image set and synthetic diagnostics

Use at least 15–30 diverse, appropriately licensed images where possible:

- natural scenes and landscapes;
- portraits;
- fine textures (foliage, fabric, hair, brick);
- text, diagrams and thin lines;
- pixel art or segmentation masks.

Begin with the deterministic synthetic examples generated by
`examples/generate_test_images.py`: a colour gradient, checkerboard/high-
contrast edges, impulse, slanted edge and sinusoidal grating. These isolate
specific mathematical properties. Preserve natural-image originals and record
their source, licence, dimensions, format and colour mode in a dataset manifest.

The optional `examples/plot_kernel_diagnostics.py` script plots the spatial
kernels, approximate frequency responses and step responses. Matplotlib is
used only to draw the curves; the kernels and numerical responses are computed
from this project's functions.

## 2. Scale factors and directions

For enlargement test 2x, 3x and 4x. For reduction test 0.75x, 0.5x and 0.25x.
Record exact integer output dimensions and avoid comparisons whose outputs have
different sizes. Analyse enlargement and reduction separately: reduction is
also a low-pass filtering/anti-aliasing problem.

## 3. Library baseline

Use Pillow's `Image.Resampling` options as a practical baseline for nearest,
bilinear, bicubic, Lanczos and BOX/area. Record Python, Pillow and NumPy
versions. Do not assume the library's coefficients, coordinate mapping,
boundary handling or precision are identical to the scratch implementation.
Pillow has no direct named equivalent for this project's Mitchell--Netravali
and prefiltered cubic B-spline implementations; report those as scratch-only.

## 4. Independent implementation

The NumPy implementation in this repository makes the following choices
explicit:

- half-pixel centre mapping by default, with optional `align_corners`;
- clamp, reflect, wrap and constant edge extension (B-spline supports clamp
  and reflect coefficient boundary conditions);
- Keys cubic convolution `a=-0.5`;
- Mitchell--Netravali `B=C=1/3` by default;
- cubic B-spline basis with a tridiagonal coefficient prefilter;
- Lanczos radius 3;
- exact pixel-footprint overlap for area resampling;
- scale-aware widening of point kernels for reduction.

Change one convention or parameter at a time when studying its influence.

## 5. Controlled degradation and ground truth

When a high-resolution image is available, use it as the reference, create a
low-resolution input with a recorded anti-alias filter/downsampling process,
then reconstruct to the original dimensions. Supply the exact same low-
resolution array to every reconstruction method.

Repeat the comparison with multiple degradation processes (for example the
scratch implementation's area, bilinear, bicubic and Lanczos filters, or a
separately documented Gaussian prefilter followed by decimation). The benchmark
creates its low-resolution input with the scratch implementation by default;
`--degradation-implementation pillow` is an explicit optional alternative for
studying library-generated degradation. A Lanczos-generated input can favour a
Lanczos reconstruction. It must not be the only degradation used in a thesis.
The original image is a known reference for this synthetic experiment, not
necessarily a perfect ground truth for arbitrary real-world resizing.

## 6. Quality evaluation

Report:

- MSE: lower is better;
- PSNR: higher is better;
- uniform-window SSIM: closer to 1 is more structurally similar.

The repository implements these metrics directly in NumPy. SSIM uses a
uniform square window (default 7x7), sample covariance correction, channel-wise
calculation and mean aggregation. Record this variant and data range; 255 is
the default for 8-bit data and 1 is appropriate for normalized [0,1] arrays.

Include visual crops and discuss edge sharpness, overshoot/undershoot, ringing,
blur, jaggedness, moire and texture retention. Metrics do not fully describe
perceived quality.

## 7. Runtime evaluation

The benchmark CLI supports one warm-up and multiple measured repetitions.
Use at least 5–10 measured repetitions for final tables and report the median
and dispersion (mean/standard deviation or interquartile range). The CSV
records median, mean, standard deviation and minimum runtime. Timing excludes
file loading, metric computation and image saving, but includes array validation
and resampling in each implementation. Record CPU, OS, Python and NumPy
versions, machine load and array dimensions.

## 8. Reproducibility manifest

For every run, record:

- image identifier/licence, source and dimensions;
- source and destination sizes and scale factors;
- implementation and exact method parameters;
- degradation/downsampling method;
- coordinate mode, boundary mode and anti-alias setting;
- colour-space, channel and alpha treatment;
- data range, SSIM window and covariance convention;
- warmups, repeat count and runtime summary;
- Python, NumPy, Pillow, OS and hardware information.

## 9. Interpretation

Separate conclusions about (a) visual quality, (b) objective metrics and
(c) processing time. Explain observed differences through kernel shape,
frequency response, support size, anti-aliasing, coordinate convention,
boundary extension, colour encoding and numerical precision. Do not declare a
universal winner from one image or one degradation filter.
